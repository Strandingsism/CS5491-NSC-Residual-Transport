# 受控训练实验：嵌入路径的因果检验（v4）

v3（Study 2）的证据来自档案中的观察数据。本目录自己训练小模型，**只改变嵌入（d_embed、div_val），解码器完全固定**，直接检验冻结的 v3 对嵌入的预测。课题 PDF 扩展方向 1 指出，受控训练比档案中的异构配置证据更强。新训练的结果是独立的新标签，不使用 final split。

## 设置

- 数据：WikiText-103 raw（Hugging Face `Salesforce/wikitext`），GPT-2 BPE 分词（50257 个 token，与档案 n_token = 50264 同一词表）。训练集 117,920,140 token，验证集 247,289，测试集 283,287。`prepare_data.py` 校验每个文件的 SHA-256。
- 模型（`txl.py`）：按档案的约定实现 Transformer-XL。相对位置注意力加记忆，Post-LN，绑定权重的自适应嵌入和自适应 softmax，头投影不绑定、尾投影绑定，cutoffs [19997, 39997]，权重初始化 N(0, 0.02)、投影初始化 N(0, 0.01)，dropout 0.1。注意力和块结构参考 NSC 作者的训练脚本（MIT 许可）。
- 训练（`train.py`）：Adam，学习率 1e-3，5% 线性预热后余弦衰减，梯度裁剪 0.25，bf16，32 条并行流 × 192 token，记忆长度 192。在完整验证集上带记忆计算 PPL。
- 硬件：试跑（第 1 节）用 NVIDIA GeForce RTX 5070 Ti Laptop GPU（12 GB）；正式面板（第 4 节）用 AutoDL 服务器的 RTX 4080 SUPER（32 GB）。PyTorch 2.9.1 + CUDA 12.8。

```powershell
pip install -r controlled/requirements.txt   # torch 需要从 CUDA 源安装，见文件内注释
.\.venv\Scripts\python.exe controlled\prepare_data.py
.\.venv\Scripts\python.exe controlled\train.py --name pilot_d256_e256 --d_model 256 --n_layer 8 --n_head 8 --d_inner 1024 --d_embed 256 --div_val 1 --tokens 2e7 --seed 0
```

## 1. 计时试跑（2026-11-03）

d_model = 256，8 层，8 头，FFN 1024（解码器 6,838,272 个参数），训练 2000 万 token（约为训练集的 1/6）。

| 运行 | d_embed | div_val | 种子 | 总参数 | 验证 PPL | 训练时间 |
|---|---:|---:|---:|---:|---:|---:|
| pilot_d256_e256 | 256 | 1 | 0 | 19.75 M | 76.88 | 370 s |
| pilot_d256_e256_s1 | 256 | 1 | 1 | 19.75 M | 78.11 | 369 s |
| pilot_d256_e64 | 64 | 1 | 0 | 10.14 M | 105.98 | 340 s |

- 吞吐约 5.4 万 token/s，显存峰值 4 GB。
- 种子差异：两个种子的 log PPL 相差 0.016（约 1.6%），与档案上从数据反推的噪声上界（约 2%）同一量级。只有两个种子，这只是粗略估计。
- 嵌入效应：d_embed 从 64 增加到 256，log PPL 降低 0.32，约为种子差异的 20 倍。在这个训练量下，嵌入效应可以被清楚地测到。
- 局限：短训练下，窄嵌入的劣势可能被放大（低频 token 的嵌入训练不足）。正式实验中需要用更长的训练检查效应是否保持。

## 2. v3 对受控面板的预测（不读任何训练结果）

解码器固定为上面的设置时，NSC = 2151.1，对所有嵌入变体**完全相同**（NSC 不看嵌入，无法区分它们）。v3 的嵌入路径容量 E：

| d_embed | div_val = 1 | div_val = 2 | div_val = 4 |
|---:|---:|---:|---:|
| 64 | 273.1 | 413.9 | 315.2 |
| 128 | 439.6 | 656.3 | 500.5 |
| 256 | 780.1 | 947.5 | 724.6 |
| 512 | 713.0 | 1205.0 | 947.4 |

可以区分 v3 与"数参数"的地方：div_val = 1 时 v3 预测 d_embed = 512 **不比 256 更好**（秩瓶颈下饱和），而总参数量预测 512 更好；v3 还预测同样 d_embed 下 div_val = 2 优于 div_val = 1。

## 3. 预注册（写于任何正式面板训练之前）

### 3.1 面板（`run_panel.py`）

| 面板 | 固定的解码器 | 变化 | 种子 | 训练量 | 次数 |
|---|---|---|---|---|---:|
| A | d=256，8 层，8 头，FFN 1024 | d_embed ∈ {64, 128, 256, 512} × div_val ∈ {1, 2, 4} | 0, 1, 2 | 2e7 token | 36 |
| B | d=512，8 层，8 头，FFN 2048 | d_embed ∈ {128, 256, 512}，div_val = 1 | 0, 1, 2 | 2e7 token | 9 |
| C | 同 A | d_embed ∈ {64, 256}，div_val = 1 | 0 | 6e7 token | 2 |

其余超参数与第 1 节相同，不随结果调整。试跑的 3 次运行不计入面板。结果指标为完整验证集的 log PPL，按种子取平均；测试集不使用。

### 3.2 冻结 v3 的预测（`analyze.py`，规格计算，不读任何训练结果）

面板 A 中 NSC 对 12 个配置完全相同（2151.1）；v3 = NSC + E，E 见第 2 节。面板 B 中 NSC = 7675.7，v3 = 8221.8 / 8555.0 / 9234.6（d_embed = 128 / 256 / 512）。

**H1（排序）**：面板 A 上 Spearman ρ(v3, −log PPL) > 0，置换检验单侧 p < 0.05。同时报告总参数量的 ρ 作为对照；NSC 全部并列，无法排序。

**H2（饱和，区分 v3 与数参数）**：div_val = 1 时，d_embed = 512 不比 256 好：mean log PPL(512) − mean log PPL(256) ≥ −2·SE。总参数量预测 512 更好。

**H3（div_val）**：同样 d_embed 下 div_val = 2 优于 div_val = 1（log PPL 差 < −2·SE），在 4 个 d_embed 中至少 3 个成立。这是有风险的预测：档案开发集上 v3 对 div_val 有过度记功的迹象（`analysis/v3_embedding_path/README.md` 第 8.2 节）。

**H4（宽模型窄嵌入）**：面板 B 中 log PPL 随 d_embed 严格下降（128 > 256 > 512）。

**C（训练量）**：d_embed 64 与 256 的 log PPL 差距在 6e7 token 时若缩小到 2e7 时的一半以下，则短训练结论需要打上明显折扣，在报告中写明。

**种子噪声**：报告面板 A、B 中配置内 log PPL 的合并标准差，并与档案上反推的上界（约 0.02）比较。

### 3.3 规则

- 无论哪条假设成立或不成立，都如实报告；不因结果增加或删除配置。
- 如果某次运行因技术原因失败（如中断），用同样的参数重跑，并在此记录。
- 训练在远程 GPU 服务器上进行；代码与本仓库此提交一致，服务器型号和用时会记录在结果中。

## 4. 结果（2026-11-03，按第 3 节预注册分析）

在 AutoDL 服务器（RTX 4080 SUPER 32 GB）上运行，代码为提交 `4388424`；它与预注册提交 `d5f15a2` 相比只给 `run_panel.py` 加了 `--shard`（两个进程并行，各跑一半），没有改动任何配置。47 次运行全部成功，没有重跑。单次用时：面板 A 326–513 s，B 476–589 s，C 1019–1248 s；两个进程并行，总墙钟约 3.3 小时（GPU 累计 6.3 小时）。

```bash
python controlled/run_panel.py --shard 0/2   # 另一个进程用 --shard 1/2
python controlled/analyze.py                 # 写出 controlled/analysis.json
```

面板 A（d_model 256），验证集 PPL，3 个种子平均（括号内为 log PPL 的标准误）：

| d_embed | div_val = 1 | div_val = 2 | div_val = 4 |
|---:|---:|---:|---:|
| 64 | 105.73 (0.004) | 110.54 (0.002) | 117.05 (0.008) |
| 128 | 91.32 (0.002) | 95.39 (0.002) | 99.54 (0.003) |
| 256 | 79.21 (0.006) | 85.64 (0.005) | 88.77 (0.008) |
| 512 | 74.18 (0.003) | 77.15 (0.005) | 79.67 (0.003) |

面板 B（d_model 512）：d_embed 128 / 256 / 512 的 PPL 为 98.05 / 75.92 / 63.49。面板 C（6e7 token）：d_embed 64 为 59.08，256 为 44.88。

| 检验 | 结果 | 结论 |
|---|---|---|
| 种子噪声 | 合并标准差 0.0150 | 低于档案上界约 0.02，与之一致 |
| H1 排序 | ρ(v3) = +0.825，p = 0.001；对照：ρ(总参数) = +0.993 | **成立**，但总参数量排得更好 |
| H2 饱和 | 512 − 256 = −0.066 ± 0.007（约 10 个标准误） | **不成立**：512 明显更好，符合总参数量的预测 |
| H3 div_val | 4 个 d_embed 下 div_val 2 都**更差**（+0.04 到 +0.08，均超过 5 个标准误） | **不成立**，方向相反 |
| H4 宽模型 | 4.585 > 4.330 > 4.151 | **成立** |
| C 训练量 | 差距 0.289 → 0.275，比值 0.95 | 嵌入效应在 3 倍训练量下基本保持，**不需要**折扣 |

### 4.1 解读

- **v3 对嵌入大小的方向是对的，对结构的判断是错的。** 在解码器固定时，更大的 d_embed 一直更好（H1、H4），这一点 NSC 完全看不到，v3 看得到。但 v3 用 ψ_MP 刻画的两个结构性预测都被否定：没有出现 d_embed = d_model 处的秩瓶颈饱和（H2），div_val 分层也不带来收益，反而在每个大小下都更差（H3）。
- **在这个受控面板上，嵌入参数量本身比 v3 的 E 更能预测结果。** 同一 d_embed 下 div_val 越大，低频 token 的嵌入维度越小、参数越少、PPL 越高；总参数量的排序几乎完全一致（ρ = 0.993）。v3 对 div_val 的加分正好与此相反，这与档案开发集上"v3 对 div_val 过度记功"的迹象（`analysis/v3_embedding_path/README.md` 第 8.2 节）一致，现在由受控实验证实。
- **对 Study 2 的含义**：v3 在档案上的提升（相对 NSC）可以被理解为"把嵌入算进容量"这一方向带来的，而不是 ψ_MP 对嵌入结构的具体刻画带来的。档案的冻结结果不变，但它的机制解释需要收窄。
- **局限**：只有一个数据集、一种模型族（Transformer-XL），训练量最多 6e7 token（约半个 epoch），远少于档案中的完整训练；面板 B 只有 3 个配置，置换检验无法达到显著（3 个点的最小 p 约 0.17）。
